00概览

本地、无 daemon、无数据库的多 agent CLI harness。把一个任务拆成 job， 每个写 job 在独立 git worktree 里由真实 CLI(codex / claude)执行，harness 负责 验证、集成、交接成一个分支 —— 全程不碰你的主工作树。

🧠
orchestrator（编排者）
你正在对话的那个 LLM 会话（Claude Code / Codex / 你自己）。决定做什么，用 shell 调 harness。提议，不直接写状态。
⌨️
harness CLI（裁判）
确定性 Go 程序。状态机 / scope / gate / verify 全由它裁决，唯一能写 .harness/。
🤖
runtime（工人）
claude 或 codex。在隔离 worktree 里真正改代码，由 --runtime 指定。两者可互换。

协议先于运行时events 是唯一真相 LLM 提议 · CLI 裁决worktree 写隔离 worker 自报不可信 · git 求真

想看单次 harness run 的逐帧动画 → harness-flow.html

01调用机制

「A 指挥 B」= 编排者是 A、worker 是 B(--runtime B)。命令完全一样， 只换「你坐在哪个会话」+「--runtime 填谁」——这就是双向对等。

  你/agent (orchestrator) ──shell──▶ harness CLI  ──spawn──▶ runtime (worker)
        │ 提议 what                     │ 裁决/求真            │ 在 worktree 改代码
        │                              ▼                      ▼
        │                     .harness/ events(真相)     .worktrees/job-id (隔离)
        │                          + views(可重建)             │ commit → job/<id>
        ▼                                                       ▼
   review 交付分支 ◀── integrate(merge) ◀── ground truth: git diff + 重跑 verify
   harness/integration/<task>                                你的主工作树: 从不被写

六条铁律

LLM 提议，CLI 裁决状态机/scope/gate/verify 判定全在确定性 CLI，绝不进 prompt。
events 是唯一真相每 actor 一个 append-only 日志；所有 JSON 视图可重建。崩溃/compact/resume 都能恢复。
worker 自报不可信changed_files/verification/usage 仅供参考；真相由 git diff + 重跑检查确立。
worktree 写隔离每个写 job 一个 worktree + job/<id> 分支；崩溃恢复=丢弃 worktree。
永不写主工作树结果交付在 harness/integration/<task> 分支，等你 merge。
push 委派orchestrator spawn 即派定，无队列、无抢单。

job 状态机

created ──▶ running ──┬─▶ completed
                      ├─▶ failed
                      ├─▶ needs-human   # 越权/失败 → 开 gate
                      └─▶ timeout
gate 处理后: needs-human ──▶ created(重跑) | cancelled(放弃)

03命令全集

按阶段分组。--session 省略时默认用最近的 session。

① setup

harness init在当前 git repo 建 .harness/(schema/reserved/contract);非 git 仓拒绝
harness session start开 session，捕获仓库基线

② work（委派与执行）

harness task create --title T [--accept A] [--budget N]建任务
harness task phase --task T --to PHASE推进 task phase(CLI 校验合法性)
harness delegate --task T --role R --runtime codex|claude …建 job(见下方常用参数)
harness run --job J把 created job 跑到终态
harness verify --task T --cmd C [--cmd …]CLI 实跑任务级验证 → verification.json
harness integrate --task T合并 job 分支 → harness/integration/T
harness handoff --task T渲染 handoff.md(jobs/验证/交付分支)

delegate 常用参数: --goal 一句目标--brief 背景 --allow 'src/**' 可写范围--deny package.json --verify '验收命令'--constraint 约束 --context 文件--from J-分析job --trellis-task slug

③ 异常 & 恢复

harness gate list | show --gate G | approve --gate G [--option …] [--files …] | reject --gate G人工 gate 处理
harness recover [--session]从事件日志重建视图;回收 stale job / 清孤儿 worktree
harness prune [--session]回收所有终态写 job 的 worktree(保留分支),防膨胀

④ hooks（runtime 侧）

harness guard pretool|posttool …PreToolUse 路径闸门 / PostToolUse diff 复核
harness hook task-stop --role worker|orchestrator …Stop / TaskCompleted 闸门

退出码: 0 ok · 10 blocked-policy · 12 needs-human · 20 verify-failed · 22 result-invalid · 30 state-corrupt · 31 lock-timeout · 32 cas-retry · 40 runtime-exec-failed · 41 budget-exceeded · 42 delegation-loop · 64 usage/非 git 仓。

04完整闭环

一个 task 从创建到交付分支的完整命令序列(真实验证过)。

# 0. 一个有提交的 git 仓
cd your-project && git init -q && git add -A && git commit -m init

# 1. 初始化 + 开 session
harness init
harness session start

# 2. 建任务
harness task create --title "add a hello file" --accept "src/hello.txt exists"
#  -> created task T-2026...

# 3. 委派一个写 job 给某 runtime
harness delegate --task T-2026... --role implementation --runtime codex \
  --goal 'Create src/hello.txt containing: hello harness' \
  --allow 'src/**' --verify 'test -f src/hello.txt'
#  -> delegated J-2026...

# 4. 执行 — worker 在隔离 worktree 改, CLI 抽结果+求真
harness run --job J-2026...
#  -> job J-2026... -> completed (ok)   [越权/失败则 needs-human]

# 5. 任务级验证 + 集成 + 交接
harness verify   --task T-2026... --cmd 'test -f src/hello.txt'
harness integrate --task T-2026...    # -> harness/integration/T-2026...
harness handoff  --task T-2026...

# 6. review 交付分支并 merge 进你的分支
git merge harness/integration/T-2026...

全程你的主工作树保持干净 —— 改动只在 job/J-… 和 harness/integration/T-… 上，直到你 merge。

05使用场景

Claude 指挥 Codex
Codex 指挥 Claude
research → implement
gate 处理
崩溃恢复

你在 Claude Code 会话里(Claude=编排者)，让它把活交给 codex 做:

harness delegate --task T-1 --role implementation --runtime codex \
  --goal "重构 src/auth，保持 API 兼容" --allow 'src/auth/**,tests/**' --verify 'npm test -- auth'
harness run --job J-1            # 在 worktree 里 spawn codex 干活
harness verify --task T-1 --cmd 'npm test'
harness integrate --task T-1 && harness handoff --task T-1

codex 在隔离 worktree 写代码，Claude Code 负责拆任务/推进/读结果/处理 gate。

你在 Codex 会话里(Codex=编排者)，同样的命令，只把 --runtime 换成 claude:

harness delegate --task T-1 --role implementation --runtime claude \
  --goal "..." --allow 'src/**' --verify '...'
harness run --job J-1            # 在 worktree 里 spawn claude 干活

命令一字不差，只换了 --runtime 和你所在的会话。这就是双向对等。

先派一个只读 analysis job 勘探代码(产出 findings)，再把它喂给 implement job —— 把「理解」当数据传递，worker 不靠冷启动瞎猜:

# 1) 勘探(read-only)，结果落 findings/<jid>.md
RJ=$(harness delegate --task T-1 --role analysis --runtime claude \
      --goal "勘探 auth: 公开API/必保错误码/薄弱点/改动建议(file:line)" --allow 'src/**')
harness run --job $RJ

# 2) 实现，--from 把上一步 findings 注入 worker 的必读清单
harness delegate --task T-1 --role implementation --runtime codex \
  --from $RJ --context 'src/auth/service.js' \
  --goal "给 login 加输入校验" --constraint '保留错误码值不变' \
  --allow 'src/auth/**' --verify '...'

效果差异:薄 goal → worker 瞎猜;富 packet(brief+约束+必读文件+验收) → worker 基于真实勘探实现，跨 runtime 理解差异在 grounding + 验收两端被吸收。

worker 越权写 / verify 失败 / 集成冲突 → job 进 needs-human 并开 gate:

harness gate list
harness gate show --gate G-1
# 批准额外文件并重跑:
harness gate approve --gate G-1 --option approve_extra_files --files 'config/**'
# 或放弃该 job 的改动(标 cancelled, 丢弃 worktree):
harness gate reject --gate G-1

resolve 后 job 移出 needs-human(重跑或取消)，不再卡 task 完成;每次都打印下一步命令。scope/secrets 由你拍板，CLI 不替你决定。

worker 被 kill / 进程崩溃 / 终端被关后:

harness recover            # 崩溃后恢复
harness prune              # 回收终态 job 的 worktree(防膨胀)

recover:从事件日志重建所有视图;探活(pid+boot-id)判定 stale job → 丢弃其 worktree 并重置/熔断;清理孤儿 worktree。互斥(recover.lock)且幂等。工作树回滚只靠 git，逻辑状态只靠 event replay。

worktree 不膨胀: 每个写 job 一个 .worktrees/<jid>(git worktree 共享 .git，每个仅一份工作区 checkout)。integrate 成功后自动回收已合并 job 的 worktree、prune 回收所有终态写 job 的、recover 清 stale/孤儿 —— 三者都保留 job/<id> 分支(轻量可回溯);needs-human/running 的 worktree 保留为现场。

06在 Claude Code / Codex 里用

一句话驱动整条闭环(init→task→delegate→run→gate→verify→integrate→handoff)。

# 装 slash command / custom prompt 到用户级
./integrations/install-integrations.sh           # 两者都装
# 或: ./integrations/install-integrations.sh claude | codex

然后在你项目的会话里(harness 在 PATH 上):

# Claude Code — 第一个词是 worker runtime
/harness-delegate codex 给 auth 模块加输入校验

# Codex — 同样的命令，选 claude 当 worker
/harness-delegate claude 给 auth 模块加输入校验
agent装到机制
Claude Code~/.claude/commands/harness-delegate.mdslash command + $ARGUMENTS
Codex~/.codex/prompts/harness-delegate.mdcustom prompt + $ARGUMENTS/$1

你对话的 agent 当 orchestrator，worker 是你点名的另一个 runtime，跑在隔离 worktree。嵌套可行(Claude Code 编排 claude -p worker，或任一方驱动 codex exec)。

07信任边界（求真）

harness 从不信 worker 说自己干了什么。每个 job 后由确定性 CLI 亲自确立事实:

改了哪些文件git diff <base> 求真 — 不信 worker 的 changed_files
验证是否通过CLI 重跑 verify 命令 — 不信 worker 的 "verification":"passed"
token 用量取 runtime 自身账目;缺失则保守估并 gate

真实例子: codex 会自带 .serena/ 工具文件写到 scope 外，claude 不会。同一套 git diff 复核抓到了 codex 的越界文件 → job 进 needs-human + gate，而不是把它们偷偷带进交付分支。 worker 行为不同，信任边界不变。

08搭配 Trellis

Trellis 管知识/规范/journal/task 编排;harness 接管「隔离执行 + 求真验收」。 .trellis/ 两边共用，零迁移。

消费 Trellis task(把它变成 harness 工单)

harness delegate --task T-1 --role implementation --runtime claude \
  --trellis-task 05-12-xterm --allow 'src/**'
# 自动读 .trellis/tasks/05-12-xterm/ :
#   task.json.title    → job goal
#   prd.md             → job brief(需求+验收)
#   implement.jsonl    → context_refs(worker 先 Read 的 spec/文件)

已在 Trellis 里 task.py start 了某 task? 省掉 --trellis-task，harness 经 task.py current 自动关联。

回写(走 Trellis 自己的脚本，格式永不漂移)

task.py set-branch把 job 分支记到 task.json(不 git commit)
add_session.py --no-commit写 journal(不替你 commit)

python 解释器不写死: $HARNESS_PYTHON → 脚本 shebang 自执行 → PATH 探 python3/python/py → 都没则跳过回写+提示。start/finish/archive 不自动调(归你在 Trellis 侧 /trellis:finish-work 驱动)。
